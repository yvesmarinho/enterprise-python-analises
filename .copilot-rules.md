Este arquivo define diretrizes gerais de comportamento, comunicação e workflow para o GitHub Copilot ao trabalhar neste projeto.

## 💬 Comunicação

### Tom e Estilo
- ✅ **Profissional e objetivo**
- ✅ **Claro e direto**
- ✅ **Técnico quando apropriado**

- ❌ Não ser verboso desnecessariamente

### Formato de Respostas
- ✅ Usar Markdown formatado
- ✅ Incluir blocos de código com syntax highlighting
- ✅ Estruturar respostas com títulos e listas
- ✅ Destacar informações importantes com **negrito** ou ⚠️
- ✅ Usar tabelas para comparações

### Explicações
- ✅ Explicar o "porquê" das decisões técnicas
- ✅ Fornecer contexto quando relevante
- ✅ Sugerir alternativas quando apropriado
- ✅ Alertar sobre potenciais problemas
- ❌ Não assumir conhecimento avançado sem verificar

## 🔄 Workflow de Trabalho

### Recuperação de Contexto (Início de Sessão)

**SEMPRE ao iniciar uma nova sessão:**

1. 📂 **Verificar estrutura de sessões anteriores**
   ```bash
   docs/sessions/YYYY-MM-DD/
   ```

2. 📖 **Ler arquivos principais**
   - `docs/INDEX.md` - Estado geral do projeto
   - `docs/TODO.md` - Tarefas pendentes
   - `docs/TODAY_ACTIVITIES.md` - Última atividade
   - Última sessão em `docs/sessions/[data-mais-recente]/`

3. 🆕 **Criar nova sessão**
   - Criar pasta `docs/sessions/YYYY-MM-DD/`
   - Criar `SESSION_RECOVERY_YYYY-MM-DD.md`
   - Criar `TODAY_ACTIVITIES_YYYY-MM-DD.md`
   - Atualizar datas em INDEX.md e TODO.md

4. 📝 **Documentar recuperação**
   - O que foi recuperado
   - Estado atual do projeto
   - Próximos passos planejados

---

### Durante a Sessão

**Documentação Contínua:**
- ✅ Atualizar `TODAY_ACTIVITIES` conforme trabalho avança
- ✅ Marcar tarefas concluídas no `TODO.md`
- ✅ Criar arquivos nas pastas corretas
- ✅ Validar código antes de marcar como "funcional"

**Organização:**
- ✅ Manter raiz limpa (apenas arquivos essenciais)
- ✅ Usar estrutura de pastas estabelecida
- ✅ Seguir nomenclatura padrão
- ✅ Arquivos temporários → `tmp/` do projeto (**NUNCA** `/tmp` do Linux)

**Validação:**
- ✅ Testar código criado
- ✅ Verificar sintaxe e lógica
- ✅ Validar contra requisitos

---

### Final de Sessão

**Documentação de Encerramento:**
1. 📄 Criar `SESSION_REPORT_YYYY-MM-DD.md`
   - Resumo do que foi feito
   - Problemas encontrados
   - Soluções implementadas
   - Próximos passos

2. ✅ Atualizar STATUS em INDEX.md
3. ✅ Atualizar progresso em TODO.md
4. 📊 Criar `FINAL_STATUS_YYYY-MM-DD.md` se for fim de milestone

## 🔧 Desenvolvimento de Código

### Python (Linguagem Principal)

**Padrões de Código:**
- ✅ Seguir PEP 8
- ✅ Usar type hints quando apropriado
- ✅ Docstrings em formato Google ou NumPy
- ✅ Nomes descritivos de variáveis e funções
- ✅ Constantes em UPPER_CASE
- ✅ Classes em PascalCase
- ✅ Funções e variáveis em snake_case

**Estrutura de Script:**
```python
"""
Breve descrição do script.

Este módulo faz X, Y e Z.
"""

import stdlib
import third_party
import local_modules

# Constants
MAX_RETRIES = 3
DEFAULT_TIMEOUT = 30

def main_function(param: str) -> bool:
    """
    Descrição da função.

    Args:
        param: Descrição do parâmetro

    Returns:
        Descrição do retorno

    Raises:
        ValueError: Quando ocorre X
    """
    pass

if __name__ == "__main__":
    main_function()
```

**Tratamento de Erros:**
- ✅ Sempre usar try/except em operações de I/O
- ✅ Capturar exceções específicas (não usar bare except)
- ✅ Logar erros apropriadamente
- ✅ Fornecer mensagens de erro úteis

**Validação:**
- ✅ Validar inputs
- ✅ Verificar tipos quando crítico
- ✅ Testar edge cases
- ✅ Documentar limitações conhecidas

---

### Dependências

**Gerenciamento:**
- ✅ Usar `uv` como gerenciador de pacotes
- ✅ Documentar todas as dependências em `pyproject.toml`
- ✅ Especificar versões (ou ranges semânticos)
- ✅ Separar dev dependencies

**Instalação:**
```bash
# Instalar dependências
uv pip install -r pyproject.toml

# Adicionar nova dependência
uv pip install package-name
# Atualizar pyproject.toml manualmente
```

## 🔍 Análise e Debugging

### Abordagem
1. **Entender o problema**
   - Ler mensagens de erro completamente
   - Identificar causa raiz
   - Verificar logs e outputs

2. **Investigar contexto**
   - Revisar código relacionado
   - Verificar dependências
   - Validar dados de entrada

3. **Propor solução**
   - Explicar o problema identificado
   - Sugerir correção
   - Alertar sobre impactos

4. **Implementar e validar**
   - Aplicar correção
   - Testar solução
   - Documentar mudança
